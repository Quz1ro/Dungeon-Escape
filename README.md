# Dungeon Escape — частина 1

Навчальний проєкт для університетського курсу **«Розробка ігрових додатків»**.
Виконавець — **один студент у ролі програміста**. Ім’я та групу студент додає
до титульного слайда перед захистом.

Dungeon Escape — невелика 2D-гра з видом зверху: гравець досліджує лабіринт,
знаходить ключ, уникає охоронця та дістається виходу. Реалізація — **Python і Pygame**.
Частина 1 містить концепцію, алгоритми та три працездатні прототипи для перевірки
механік. Це ще не завершена гра для випуску.

![Об’єднаний прототип гри](presentation/images/prototype-03.png)

## Що реалізовано

- Рух по клітинках, стіни та перевірка меж карти.
- Підбирання одного ключа й перевірка умови відкриття виходу.
- Ворог із заданим маршрутом патрулювання у прототипах 2 і 3.
- Початковий екран, перемога, поразка, повторна спроба та закриття вікна.
- Три окремі сценарії запуску зі спільною перевіреною логікою.
- Українські повідомлення та інтерфейс із геометричних фігур.

Спрайти, звук, плавний рух, переслідування гравця, збереження прогресу та набір
послідовних рівнів **не реалізовані**. Частина з них розглядається у
[плані наступної частини](docs/implementation-plan.md); це не обіцянка готових функцій.

## Встановлення та запуск

Потрібні Python **3.10 або новіший**, `pip` і локальний графічний сеанс для гри у вікні.
Перевірено у Linux на Python **3.12.14**, Pygame **2.6.1**. Додаткові сервери,
ключі API, облікові записи та завантаження ігрових ресурсів не потрібні.
Під час встановлення потрібен доступ до PyPI; після цього гра працює локально.

З кореня репозиторію:

```bash
python -m venv .venv
```

Активація у Linux / macOS:

```bash
source .venv/bin/activate
```

Активація у Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Потім встановіть залежність і запустіть один із прототипів:

```bash
python -m pip install -r requirements.txt
python prototypes/01_key_and_exit.py
python prototypes/02_enemy_patrol.py
python prototypes/03_dungeon_escape.py
```

Кожна команда запускає окреме вікно; закрийте його перед запуском наступної.
Якщо активація недоступна, викликайте `.venv/bin/python` у Linux або
`.venv\Scripts\python.exe` у Windows замість `python`.
Версію Pygame зафіксовано в `requirements.txt`; сторонніх залежностей для тестів немає.

| Клавіші | Дія |
| --- | --- |
| Enter | Почати з початкового екрана |
| Стрілки або W, A, S, D | Один крок по клітинках; утримання повторює кроки |
| R | Почати поточний прототип заново під час гри або після її завершення |
| Esc або закриття вікна | Завершити програму |

Після підбирання ключа він зникає з поля, а вихід стає зеленим. Синє коло —
гравець, червоний квадрат — ворог, золотий символ — ключ, «В» — вихід.
Дрібні точки показують маршрут патруля. Діагонального руху немає.

## Перевірка

```bash
python -m unittest discover -s tests -v
python -m pip check
```

Тести інтерфейсу самі вибирають драйвер SDL `dummy`, коли змінна `SDL_VIDEODRIVER`
ще не задана. Якщо в середовищі вже задано інший недоступний драйвер, явно
встановіть `SDL_VIDEODRIVER=dummy` для перевірки.
Тести виконують реальні операції Pygame з поверхнями та подіями без видимого вікна.

Швидка перевірка циклу програми у хмарному Linux без монітора:

```bash
SDL_VIDEODRIVER=dummy python prototypes/01_key_and_exit.py --smoke-test
SDL_VIDEODRIVER=dummy python prototypes/02_enemy_patrol.py --smoke-test
SDL_VIDEODRIVER=dummy python prototypes/03_dungeon_escape.py --smoke-test
```

Ці команди запускають 8 кадрів після події Enter і закривають програму через подію
QUIT. Для знімка поля додайте `--screenshot /tmp/dungeon-escape.png`.
Для звичайної гри `dummy` не використовуйте: він не показує вікна та не приймає
введення від фізичної клавіатури.

Результати й обмеження перевірки: [звіт](docs/validation.md).

## Структура файлів

```text
Dungeon-Escape/
├── README.md                       # Опис, встановлення та запуск
├── requirements.txt                # Pygame 2.6.1
├── docs/
│   ├── concept.md                  # Концепція, правила та ігровий цикл
│   ├── analogues.md                # Порівняння з Pac-Man та Chip’s Challenge
│   ├── diagrams.md                 # Блок-схеми та діаграма станів Mermaid
│   ├── pseudocode.md               # Псевдокод, узгоджений із реалізацією
│   ├── implementation-plan.md      # План частини 2 для одного програміста
│   └── validation.md               # Відтворювані перевірки й результати
├── prototypes/
│   ├── README.md                   # Гіпотези та сценарії трьох прототипів
│   ├── 01_key_and_exit.py          # Лабіринт без ворога
│   ├── 02_enemy_patrol.py          # Відкрита кімната з патрулем
│   └── 03_dungeon_escape.py        # Лабіринт із ключем і патрулем
├── src/dungeon_escape/
│   ├── __init__.py
│   ├── __main__.py                 # Додатковий запуск як модуля
│   ├── model.py                    # Правила, стани, валідація карт
│   ├── levels.py                   # Три карти й маршрути патруля
│   └── app.py                      # Вікно, події та малювання Pygame
├── tests/
│   ├── test_model.py               # Правила та пошук шляху до перемоги
│   └── test_app.py                 # Події, відображення та український шрифт
└── presentation/
    ├── slides.md                   # Дев’ять слайдів для захисту
    ├── speaker-notes.md            # Нотатки доповідача
    ├── demo.md                     # Сценарій демонстрації й відповіді
    └── images/                     # Знімки запущених прототипів
        ├── prototype-01.png
        ├── prototype-02.png
        └── prototype-03.png
```

`src` містить спільну логіку, щоб виправлення правил діяли в усіх прототипах.
`prototypes` містить невеликі точки запуску й опис навчальних експериментів.
Тестовий пошук шляху використовується лише для перевірок; ворог у грі ним не користується.
Діаграми Mermaid відображаються на GitHub; для локального перегляду потрібен
Markdown-переглядач із підтримкою Mermaid. Слайди — звичайний Markdown;
залежності для перегляду текстових матеріалів встановлювати не потрібно.
