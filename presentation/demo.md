# Сценарій демонстрації

## Підготовка перед захистом

1. Відкрити `slides.md` у Markdown-переглядачі; перевірити зображення та Mermaid.
   За потреби перенести дев’ять слайдів у редактор презентацій.
   Готовий файл PowerPoint або PDF до частини 1 не входить.
2. У графічному сеансі встановити залежності за README й відкрити термінал
   у корені репозиторію. Активувати `.venv`.
3. Запустити `python -m unittest discover -s tests -v` та переконатися, що є
   `Ran 24 tests` і `OK`, без пропусків або помилок.
4. Завчасно пройти рівні на комп’ютері для показу. Живий показ не використовує
   `SDL_VIDEODRIVER=dummy`; ця змінна призначена для автоматичних перевірок.
5. Залишити знімки `images/prototype-*.png` як резерв для показу без графічного сеансу.

## Показ, 2–3 хвилини

| Крок | Дія | Очікуваний результат |
| --- | --- | --- |
| 1 | `python prototypes/01_key_and_exit.py`, Enter | Відкритий лабіринт без ворога |
| 2 | Натиснути стрілку в напрямку стіни | Гравець не проходить крізь стіну |
| 3 | Показати ключ і вихід; за наявності часу підібрати ключ | Ключ зникає, статус і колір виходу змінюються |
| 4 | Esc; `python prototypes/02_enemy_patrol.py`, Enter | Видно рух і розворот охоронця |
| 5 | Зайти на маршрут і дочекатися контакту | Екран поразки, ворог зупинився |
| 6 | R | Позиції та ключ відновлено |
| 7 | Esc; `python prototypes/03_dungeon_escape.py`, Enter | Показано лабіринт із ключем і патрулем |
| 8 | Коротко показати вибір маршруту; якщо є час — пройти рівень | Видно поєднання механік; після виходу з ключем — перемога |
| 9 | Esc | Програма завершується |

Не потрібно вміщувати повне проходження всіх трьох карт у короткий показ.
Прохідність додатково підтверджується тестами, а не лише словами доповідача.

## Питання, до яких варто підготуватися

**Чому три прототипи мають спільний код?**
Вони досліджують різні конфігурації механік. Спільна модель запобігає розбіжностям
у правилах і дозволяє повторно використати тести.

**Чи переслідує ворог гравця?**
Ні. У цій частині він проходить заданий маршрут туди й назад. Алгоритму
пошуку гравця немає.

**Чому вихід без ключа можна пройти?**
Ключ дозволяє завершення рівня. Це правило не робить вихід стіною; при вході
без ключа виводиться підказка, і гравець може повернутися за ключем.

**Чи доведено, що гра цікава?**
Ні. Автоматичні перевірки підтверджують правила та наявність переможного шляху.
Оцінка цікавості й складності потребує спроб гравців у наступній частині.

**Що буде, якщо комп’ютер малює кадри повільніше?**
Патруль використовує час, а не кількість кадрів. Довгий кадр обробляє кілька
кроків, перевіряючи зіткнення після кожного. Гравець рухається за подіями клавіатури.

**Що ще не зроблено?**
Остаточне оформлення, ручна перевірка з людьми, звук і пакет для передачі.
Перелік і пріоритети наведено у `docs/implementation-plan.md`.
