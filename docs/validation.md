# Звіт перевірки частини 1

Перевірка виконана **24 жовтня 2026 року** у хмарному Linux:
Python 3.12.14, Pygame 2.6.1, SDL 2.28.4. Залежність встановлена у локальне `.venv`.
Графічного сеансу для ручної гри немає; використано штатний SDL-драйвер `dummy`.

## Виконані перевірки

| Перевірка | Фактичний результат |
| --- | --- |
| Встановлення `requirements.txt` | Pygame 2.6.1 встановлено з PyPI |
| `python -m pip check` | Конфліктів залежностей немає |
| `python -m unittest discover -s tests -v` | **24 тести пройдено**, помилок, очікуваних помилок і пропусків немає |
| Логіка без графічної оболонки | 21 тест у `test_model.py` пройдено |
| Інтеграція з Pygame | 3 тести у `test_app.py` пройдено |
| Кожний із трьох запусків із `--smoke-test` | Перехід MENU → PLAYING, 8 кадрів, завершення через QUIT → EXIT; код виходу 0 |
| Знімки прототипів | Три PNG створено малюванням Pygame, а не макетуванням |
| Українська кирилиця | Вбудований шрифт має гліфи всього українського алфавіту |

Основні команди з кореня репозиторію після активації `.venv`:

```bash
python -m pip check
python -m unittest discover -s tests -v
SDL_VIDEODRIVER=dummy python prototypes/01_key_and_exit.py --smoke-test --screenshot presentation/images/prototype-01.png
SDL_VIDEODRIVER=dummy python prototypes/02_enemy_patrol.py --smoke-test --screenshot presentation/images/prototype-02.png
SDL_VIDEODRIVER=dummy python prototypes/03_dungeon_escape.py --smoke-test --screenshot presentation/images/prototype-03.png
```

Знімки в `presentation/images` показують початок активної гри. У режимі перевірки
Enter та QUIT додаються програмно. Для звичайної гри ці події надходять від користувача.

## Що саме перевіряють тести

- Стіни, межі карти, заборона діагонального кроку й стрибка через клітинку.
- Підбирання та збереження ключа; перемога лише після нього.
- Вхід у замкнений вихід не дає перемоги й дозволяє відійти назад.
- Гравець заходить у ворога; ворог заходить у гравця.
- Зіткнення має пріоритет над ключем і виходом.
- Таймер, розворот патруля, кілька кроків за довгий кадр і негайна зупинка при контакті.
- Меню та кінцеві стани блокують рух; R скидає позиції, ключ, напрям і таймер.
- Завершення працює з усіх основних станів; наступна клавіша R не скасовує EXIT.
- Некоректні карти, маршрути, інтервали та час кадру відхиляються.
- Створюються поверхні Pygame, обробляються події клавіатури та закриття,
  малюються поле, меню, перемога і поразка.

Для перевірки відображення поразки інтеграційний тест ставить гравця на наступну
клітинку патруля та викликає оновлення. Природні зіткнення з обох напрямків
окремо перевірені тестами моделі.

## Перевірка прохідності

Статичної досяжності ключа та виходу недостатньо для карти з ворогом.
Тому `winning_actions` у `tests/test_model.py` шукає шлях у просторі станів:

```text
(позиція гравця, наявність ключа, індекс ворога, напрям патруля)
```

Пошук перебирає чотири кроки та очікування. Після кожної дії оновлюється патруль
на один його інтервал; програшні стани відкидаються. Це скінченний простір,
бо карти й маршрути скінченні, а повторні стани не розглядаються знову.
Накопичений час не включено до ключа пошуку, бо в цій перевірці кожне оновлення
має рівно один інтервал і повертає залишок таймера до нуля.

Для **кожного з трьох рівнів знайдено шлях**, який відтворено на новій моделі
до стану `WON` із ключем на виході. Інтеграційний тест додатково відтворив
переможні дії через клавіатурні події Pygame з малюванням після кожної дії.
Пошук дає свідок прохідності за вибраного темпу, а не гарантію виграшу
за будь-якого введення або оцінку зручності керування.

## Межі результату

Технічні перевірки завершено успішно; відомих збоїв у перевірених правилах немає.
Ручна гра з фізичною клавіатурою та дисплеєм, перевірка на Windows / macOS і
спроби інших людей **не виконані**. Їх потрібно провести перед фінальним захистом.
Безекранний запуск не підтверджує якість аудіо, плавність на реальному моніторі
або збалансованість складності; аудіосистеми у прототипах взагалі немає.

Готовність поточного середовища не означає публікацію його конфігурації або
перевірку відновлення в новому хмарному завданні. Ці операції виконуються окремо.
