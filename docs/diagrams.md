# Блок-схеми та стани гри

Головний цикл реалізовано в `Application.run`, обробку клавіш —
в `Application.handle_event`, правила руху — в `Game.move` та `Game.update`.

## Блок-схема основного алгоритму

```mermaid
flowchart TD
    A([Початок]) --> B[Перевірити карту; створити модель, вікно та шрифти]
    B --> C[Стан MENU; початкові позиції; ключа немає]
    C --> D{Стан EXIT?}
    D -- Так --> Z[Звільнити ресурси Pygame]
    Z --> END([Кінець])
    D -- Ні --> E[Обмежити частоту кадрів; виміряти час dt]
    E --> F{Є наступна подія?}
    F -- Так --> G{Закриття вікна або Esc?}
    G -- Так --> H[Установити EXIT]
    H --> F
    G -- Ні --> I{Стан EXIT?}
    I -- Так --> F
    I -- Ні --> J{Enter у MENU?}
    J -- Так --> K[Скинути світ; установити PLAYING]
    K --> F
    J -- Ні --> L{R поза MENU?}
    L -- Так --> K
    L -- Ні --> M{Команда руху у PLAYING?}
    M -- Так --> N[Виконати спробу руху та перевірити наслідки]
    N --> F
    M -- Ні --> F
    F -- Ні --> O{Стан PLAYING і є ворог?}
    O -- Так --> P[Додати dt до таймера ворога]
    P --> Q{Таймер не менший за інтервал?}
    Q -- Так --> R[Відняти інтервал; крок патруля з розворотом на кінці]
    R --> S{Ворог на клітинці гравця?}
    S -- Так --> T[Установити LOST; припинити кроки ворога]
    S -- Ні --> Q
    O -- Ні --> U{Стан EXIT?}
    Q -- Ні --> U
    T --> U
    U -- Так --> D
    U -- Ні --> V[Намалювати поле, статус та відповідний екран]
    V --> D
```

`dt` — тривалість кадру в секундах.

## Блок-схема спроби руху

```mermaid
flowchart TD
    A([Команда руху]) --> B{PLAYING і напрям дозволений?}
    B -- Ні --> Z([Повернутися до обробки подій])
    B -- Так --> C[Обчислити сусідню клітинку]
    C --> D{Клітинка в межах карти й не стіна?}
    D -- Ні --> Z
    D -- Так --> E[Перемістити гравця]
    E --> F{На клітинці є ворог?}
    F -- Так --> G[Установити LOST і повідомлення]
    G --> Z
    F -- Ні --> H{Тут ключ і він ще не взятий?}
    H -- Так --> I[Зберегти ключ; оновити повідомлення]
    H -- Ні --> J{Це клітинка виходу?}
    I --> J
    J -- Ні --> Z
    J -- Так --> K{Ключ є?}
    K -- Так --> L[Установити WON і повідомлення]
    K -- Ні --> M[Показати підказку про замок; залишити PLAYING]
    L --> Z
    M --> Z
```

Зіткнення перевіряється перед ключем і виходом. Після переходу в `WON`
або `LOST` рух гравця та ворога зупиняється.

## Діаграма станів

```mermaid
stateDiagram-v2
    state "Початковий екран" as MENU
    state "Гра триває" as PLAYING
    state "Перемога" as WON
    state "Поразка" as LOST
    state "Завершення програми" as EXIT

    [*] --> MENU: запуск
    MENU --> PLAYING: Enter / нова спроба
    PLAYING --> PLAYING: R / скидання світу
    PLAYING --> WON: вихід із ключем без зіткнення
    PLAYING --> LOST: контакт із ворогом
    WON --> PLAYING: R / нова спроба
    LOST --> PLAYING: R / нова спроба
    MENU --> EXIT: Esc або закриття вікна
    PLAYING --> EXIT: Esc або закриття вікна
    WON --> EXIT: Esc або закриття вікна
    LOST --> EXIT: Esc або закриття вікна
    EXIT --> [*]: звільнення ресурсів
```

| Стан | Оновлення світу | Допустимі основні команди |
| --- | --- | --- |
| MENU | Немає | Enter, Esc, закриття вікна |
| PLAYING | Рух за подіями, патруль за таймером | Рух, R, Esc, закриття вікна |
| WON | Немає | R, Esc, закриття вікна |
| LOST | Немає | R, Esc, закриття вікна |
| EXIT | Немає, цикл завершується | Нові ігрові команди ігноруються |

Ключ — змінна всередині світу, а не окремий стан гри. Окремого стану паузи
та повернення до початкового екрана під час спроби немає. У прототипі 1
перехід до `LOST` недосяжний, бо відсутній ворог.
