# Концепція гри

Dungeon Escape — невелика гра-лабіринт із видом зверху. Персонаж опинився
в підземеллі й має знайти ключ від виходу. На шляху патрулює охоронець.

Мета проєкту — реалізувати основні елементи 2D-гри: керування персонажем,
зіткнення, взаємодію з предметами, поведінку ворога та зміну ігрових станів.
Проєкт розрахований на одного розробника в ролі програміста.

## Мета гри

Для перемоги потрібно підібрати ключ і дійти до виходу. Контакт з охоронцем
завершує спробу поразкою. У першому прототипі ворога немає.

Увесь рівень видно на екрані. Можна заздалегідь обрати маршрут і спостерігати
за патрулем. Обмеження часу немає.

## Механіки

| Механіка | Правило |
| --- | --- |
| Рух | Чотири напрямки, один крок — одна клітинка |
| Стіни | Блокують переміщення |
| Ключ | Автоматично підбирається при вході на клітинку та зберігається до перезапуску |
| Вихід | Із ключем дає перемогу; без ключа показує повідомлення про замок |
| Патруль | Рухається заданим маршрутом туди й назад |
| Зіткнення | Гравець і ворог на одній клітинці — поразка |
| Перезапуск | Відновлює позиції, ключ і таймер ворога |

На клітинку виходу можна зайти без ключа й повернутися назад за ним.
Після підбирання ключ зникає з поля, а вихід стає зеленим.

Ворог не переслідує гравця. У прототипі 2 він робить крок раз на 0,45 с,
у прототипі 3 — раз на 0,60 с. Точки на підлозі показують його маршрут.

## Ігровий цикл

1. Початковий екран, Enter для початку.
2. Дослідження лабіринту й пошук ключа.
3. Вибір безпечного шляху повз патруль до виходу.
4. Перемога або поразка.
5. R для повторної спроби або Esc для завершення.

У кожному кадрі обробляються події, виконується рух гравця, оновлюється
патруль і малюється поле. Світ оновлюється лише у стані `PLAYING`.
Зіткнення перевіряється раніше за підбирання ключа й перемогу.
Якщо гравець уже виграв, ворог у цьому кадрі більше не рухається.

## Реалізація

Використано Python і Pygame. Карта записана рядками: `#` — стіна,
`.` — підлога, `P` — старт, `K` — ключ, `X` — вихід.
Перед запуском перевіряються розміри карти, доступність ключа та виходу,
а також маршрут ворога.

Правила зберігаються в `model.py`, карти — у `levels.py`, обробка клавіш
і малювання — у `app.py`. Усі прототипи використовують цю спільну логіку.
Графіка складається з геометричних фігур; звук поки не реалізований.
