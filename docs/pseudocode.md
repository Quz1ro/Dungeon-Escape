# Псевдокод логіки гри

Логіка реалізована в `src/dungeon_escape/model.py`, обробка подій — в `app.py`.
Координата — пара `(x, y)`. Напрям — один із `(0, −1)`, `(0, 1)`, `(−1, 0)`, `(1, 0)`.

## Підготовка рівня

```text
ПЕРЕВІРИТИ_РІВЕНЬ(рівень):
    вимагати прямокутну карту розміром щонайменше 3 × 3
    вимагати лише символи # . P K X та стіни на всій зовнішній межі
    вимагати рівно по одному P, K, X
    вимагати скінченний додатний інтервал кроку патруля
    обходом у ширину знайти клітинки, досяжні зі старту без проходу крізь стіни
    вимагати, щоб ключ та вихід належали до досяжних клітинок
    ЯКЩО маршрут ворога не порожній:
        вимагати принаймні 2 клітинки, усі досяжні
        вимагати, щоб початкова клітинка ворога не збігалася зі стартом гравця
        вимагати суміжність кожної пари сусідніх точок маршруту
    при порушенні — повідомити помилку й не починати гру

СКИНУТИ_СВІТ(новий_стан = PLAYING):
    стан ← новий_стан
    гравець ← координата P
    є_ключ ← НІ
    індекс_ворога ← 0
    напрям_патруля ← +1
    таймер_ворога ← 0
    повідомлення ← "Знайдіть ключ і дістаньтеся виходу."
```

Порожній маршрут означає відсутність ворога. Непорожній маршрут проходиться
туди й назад, а не замикається стрибком від кінця до початку.

## Головний цикл і події

```text
ПЕРЕВІРИТИ_РІВЕНЬ(обрана_карта)
створити вікно, шрифти та годинник Pygame
СКИНУТИ_СВІТ(MENU)

ПОКИ стан ≠ EXIT:
    dt ← час від попереднього кадру в секундах; обмежити частоту до 60 кадрів/с

    ДЛЯ КОЖНОЇ події Pygame:
        ЯКЩО подія закриття АБО натиснуто Esc:
            стан ← EXIT
        ІНАКШЕ ЯКЩО стан = EXIT:
            ігнорувати подію
        ІНАКШЕ ЯКЩО натиснуто Enter:
            ЯКЩО стан = MENU: СКИНУТИ_СВІТ(PLAYING)
        ІНАКШЕ ЯКЩО натиснуто R І стан ≠ MENU:
            СКИНУТИ_СВІТ(PLAYING)
        ІНАКШЕ ЯКЩО натиснуто стрілку або WASD:
            СПРОБУВАТИ_РУХ(відповідний_напрям)

    ОНОВИТИ_ВОРОГА(dt)
    ЯКЩО стан = EXIT: завершити цикл
    намалювати карту, ключ за його наявності на полі, вихід, ворога та гравця
    намалювати повідомлення й підказки
    ЯКЩО стан = MENU, WON або LOST: намалювати відповідний екран поверх поля
    показати новий кадр

звільнити ресурси Pygame
```

## Рух, ключ і вихід

```text
СПРОБУВАТИ_РУХ(напрям):
    ЯКЩО стан ≠ PLAYING АБО напрям не один із чотирьох дозволених:
        ПОВЕРНУТИСЯ
    ціль ← гравець + напрям
    ЯКЩО ціль за межами карти АБО є стіною:
        ПОВЕРНУТИСЯ

    гравець ← ціль
    ЯКЩО ПЕРЕВІРИТИ_ЗІТКНЕННЯ(): ПОВЕРНУТИСЯ

    ЯКЩО гравець = координата K І є_ключ = НІ:
        є_ключ ← ТАК
        повідомлення ← "Ключ знайдено! Тепер прямуйте до виходу."

    ЯКЩО гравець = координата X:
        ЯКЩО є_ключ:
            стан ← WON
            повідомлення ← "Ви вибралися з підземелля!"
        ІНАКШЕ:
            повідомлення ← "Вихід замкнено. Спершу знайдіть ключ."
            // Стан залишається PLAYING, від виходу можна відійти.

ПЕРЕВІРИТИ_ЗІТКНЕННЯ():
    ЯКЩО ворог існує І гравець = маршрут[індекс_ворога]:
        стан ← LOST
        повідомлення ← "Вас упіймав охоронець. Спробуйте ще раз."
        ПОВЕРНУТИ ТАК
    ПОВЕРНУТИ НІ
```

## Патруль

```text
ОНОВИТИ_ВОРОГА(dt):
    вимагати, щоб dt був скінченним та невід’ємним
    ЯКЩО стан ≠ PLAYING АБО ворога немає: ПОВЕРНУТИСЯ
    таймер_ворога ← таймер_ворога + dt

    ПОКИ таймер_ворога ≥ інтервал_кроку:
        таймер_ворога ← таймер_ворога − інтервал_кроку
        наступний ← індекс_ворога + напрям_патруля
        ЯКЩО наступний виходить за межі масиву маршруту:
            напрям_патруля ← −напрям_патруля
            наступний ← індекс_ворога + напрям_патруля
        індекс_ворога ← наступний
        ЯКЩО ПЕРЕВІРИТИ_ЗІТКНЕННЯ(): припинити цикл кроків
```

Зіткнення перевіряється після кожного кроку, тому довгий кадр не дозволяє ворогу
проскочити крізь нерухомого гравця. Команди гравця опрацьовуються раніше за
оновлення патруля: спроба зайти на поточну клітинку ворога одразу дає поразку.

## Основні умови

1. Гравець завжди на прохідній клітинці: початкова позиція перевірена,
   а наступна призначається лише після перевірки меж і стіни.
2. Ворог завжди на своєму маршруті: індекс перевіряється до присвоєння,
   а валідація вимагає щонайменше дві точки й суміжні кроки.
3. Ключ може змінитися з «немає» на «є» лише при відвідуванні K;
   скидання — лише на новій спробі.
4. `WON` установлюється лише після безпечного входу на X із ключем.
   `LOST` установлюється лише при рівності координат гравця та ворога.
5. У `MENU`, `WON`, `LOST`, `EXIT` світ не рухається.
   Після результату його може скинути R, після EXIT — уже ні.

Результати перевірки цих правил наведено у [звіті](validation.md).
